# Mobile Activity Log — app side (decided 2026-10-20)

Goal: record what each user does in the app (open, permissions, recording, menus, publishing, …) as `time | action | meta`, buffer it on the device and upload it in batches, so the backend can print a clear per-user timeline. Backend side + table: `/home/haku/projects/Next.js/Social-Media-Manager/to-build/tasks.md` (contract copied below).

## Decisions
- **Reusable logger** `activitylog/ActivityLog`: static facade, `ActivityLog.log("record_stop", "duration_ms", 92000, "source", "button")` (meta optional, pairs). Never throws, never blocks the UI: one background executor, every call wrapped in try/catch; not initialised or any failure = silently dropped. Not named `SlideLogger` (that is the debug file logger).
- **What is logged**: in-app actions only. Meta is flat scalars: ≤10 keys, key `^[a-z0-9_]{1,24}$`, string ≤64, ≤512 B in total; violators are dropped. Never in meta: email, tokens, file names, topic/caption text, channel or account names, URLs with query. Allowed: counts, durations, enum-like ids (`youtube`, `camera`), on/off, error kinds. Logging is always on (no opt-out switch); the owner updates the privacy policy.
- **Event** = `{t epoch ms UTC, tz minutes, s session id, a action ^[a-z0-9_]{1,48}$, m meta?}`. Session id = random 8 chars, new after 30 min in the background.
- **Identity**: `deviceId` = SHA-256 of the MediaDrm Widevine device-unique-id (salted `facecam-activity-v1`), first 16 bytes as a UUID; never send the raw id. MediaDrm missing or throwing (emulator, no Widevine) → random UUID. Both cached in a plain SharedPreferences file `activity_log_prefs`, **not** `SecureKeyValueStore` (that store is cleared at sign-out). Exclude that file from cloud backup and device transfer (`data_extraction_rules.xml`), or a restore would copy one deviceId to a second phone. Sent with every batch; once signed in the server links the earlier anonymous rows to the account by this id (no app work needed).
- **Buffer**: Room table `activity_events`, capped at 2000 rows; when full the oldest are dropped and one `log_overflow {dropped}` event is added.
- **When to send** (`UploadPolicy`, pure): send when EITHER (a) pending ≥ 10 and ≥ 15 min since the last send/attempt-success — heavy users may send several times a day, the cooldown stops a click burst sending every 10 clicks; OR (b) pending ≥ 1 and ≥ 3 days since the last successful send (clock starts at first run) — light users still get flushed. A send drains the buffer oldest-first in batches of ≤100 (≤5 batches per run, then reschedules).
- **How**: WorkManager, `NetworkType.UNMETERED` (Wi-Fi only, never mobile data), works with the app closed. Trigger (a) is checked after each logged event and enqueues a unique one-time job (delayed by the remaining cooldown); trigger (b) is a unique periodic job every 12 h. The worker re-checks the policy before sending.
- **Reliability**: each batch gets a `batch_id` stored on its rows before the first attempt, so a retry resends the identical batch (server is idempotent). Success (204) deletes the rows and sets `lastSendAt`. IO error / 429 / 5xx → keep rows, WorkManager backoff, `lastSendAt` untouched. 400 / 413 → that batch is poison: delete it, log nothing, carry on.
- **Auth**: if `store.hasSession()`, send through `AuthRepository.executeAuthed` (refreshes the token like any call; a refresh the server rejects ends the session exactly as it would for any other request); on `AuthException` resend the same batch anonymously. No session → anonymous.

# Paid features by tier — app side (decided 2026-10-20)

Goal: some features need a paid tier (Starter / Pro / Agency, more can be added). Each feature has one lowest plan, set on the server; the app checks it offline from a signed token and shows a friendly upgrade sheet. Backend side, decisions and token format: `/home/haku/projects/Next.js/Social-Media-Manager/to-build/tasks.md` (contract copied below). Same RULE as above (no gradle, no tests, no emulator). Supersedes the anonymous-device design in `pro-features-initila-plan.md`: accounts (email OTP, optional), PayPal tiers and the user's plan already exist on the backend, so restore = sign in on the new phone. Code paths are relative to `app/src/main/java/com/jovoc/facecampresentationrecorder/`.

## How to change things later
- **Move a feature to another plan**: one value in the backend's `PRICING.features`; phones follow on their next refresh. Mirror it in `entitlements/Feature.DEFAULT_LOWEST` at the next release (only used before the first token).
- **Add a tier**: backend only (the server sends plan names, prices and order in `catalogue`); optionally add it to `Feature.PLAN_ORDER`.
- **Add a gateable feature**: constant + default line in `Feature`, `Entitlements.has()` at its UI entry and at the point where it runs.

## Decisions
- Starting map (lowest plan): `crop_9_16` FREE · `floating_cam` FREE · `drawing_board` FREE · `slide_ink` FREE · `auto_publish` FREE · `crop_4_5` STARTER · `crop_1_1` STARTER · `bg_replace` PRO · `bg_custom` PRO. Record, topics, my videos and manual publish are never gated.
- **Check** = `Entitlements.has(Feature.BG_REPLACE)`: static, in-memory, never throws, never touches the network, never blocks the UI. Valid token → its `features`; no valid token → Free defaults (`Feature.DEFAULT_LOWEST` entries that are FREE). Free features keep working offline and without an account.
- **Token valid** when: ES256 signature verifies against `BuildConfig.ENTITLEMENT_PUBLIC_KEYS` (kid → base64 SPKI; JWS r||s converted to DER for `Signature("SHA256withECDSA")`); `now < exp`; clock not rolled back (`now ≥ max(iat seen) − 24 h`); `sid` equals `TokenStore.sessionId()`, or the token has no `sid` and there is no session. Anything else → Free; never a crash.
- **Storage**: plain SharedPreferences `entitlements_prefs` (token, catalogue JSON, lastFetchAt, maxIat) — the token is signed, nothing secret. Cleared on sign-out and when the session id changes. Excluded from backup / device transfer.
- **Refresh** (background executor, single in-flight, never blocks): app foreground when lastFetch > 6 h or the token is past half its life; after sign-in; after a workspace switch; on return from the billing page (now, +3 s, +10 s until the plan changes); after any 403 `FEATURE_NOT_IN_PLAN`. Signed in → `AuthRepository.quietAccessToken()` (no "session ended" UI from a background call) + `x-workspace-id`; no usable token → skip, keep the current one. Signed out → anonymous call. Only a verified 200 replaces the stored token; 401 / 403 / 429 / 5xx / IO keep it (never downgrade on an error).
- **Upgrade sheet** (`PaywallSheet`): feature name, one-line benefit, tier badge, price per month (from `catalogue`). Build flag `BuildConfig.CHECKOUT_LINK`:
  - `"web"`: signed out → "Sign in to upgrade" (sign-in, then refresh; done if already entitled) · signed in → "Upgrade to <Tier>" → `POST /public/v1/web-link {target:'billing', identifier:<tier>}` → browser (signed in, tier highlighted).
  - `"none"` (Play-safe): no buy link; "Available on <Tier>." + "Already subscribed? Sign in" / "Refresh".
  - Debug defaults to `"web"`, release to `"none"` until the owner has checked Play's rules for the target countries.
  - Both: "Already upgraded? Refresh". On return: if granted → close, run the action the user tapped, toast "<Tier> unlocked".
- **Locked features stay visible** with a small tier badge; tapping opens the sheet. A locked toggle stays off.
- **Lapse / downgrade**: stored settings are kept but ignored (`RecordSettings` getters return `stored && has(feature)`); custom backgrounds are kept on disk but not selectable (a selected one falls back to the first built-in); one notice on the next app open: "Your plan ended. <Tier> features are off. Your recordings are safe." Existing recordings and crops are never touched.
- **Never mid-recording**: the recording reads entitlements once at start and keeps that snapshot until it stops.
- **Account screen**: "Plan: <name>" row; tap → plans sheet listing each tier's features.
- Activity log: `paywall_view {feature, plan}` · `paywall_action {action: upgrade|signin|refresh|close, feature}` · `entitlement_change {from, to}`.
- No numeric limits this round (e.g. `UserBackgrounds.MAX_UPLOADS` stays 5).

## API contract (from backend — keep exact)
`GET /entitlements` on `BuildConfig.API_BASE_URL`, `Authorization: Bearer` optional, `x-workspace-id` optional →
`200 { token, plan, refreshAfter, catalogue:{ plans:[{key,name,monthlyPriceCents,currency}], features:{<feature>:<lowest plan>} } }`; JWS header `{alg:'ES256',typ:'JWT',kid}`, payload `{v:1, plan, features[], sid?, sub?, ws?, iat, exp}` (epoch s, 14-day life) · 401 `TOKEN_EXPIRED`/`SESSION_REVOKED` · 403 `WORKSPACE_FORBIDDEN` · 429 · 503.
Server-run feature not in plan: 403 `{statusCode, code:'FEATURE_NOT_IN_PLAN', feature, requiredPlan}`.
`POST /public/v1/web-link {target:'billing', identifier:<tier key>}` → `{url}`.
